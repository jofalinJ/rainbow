# Razorpay setup plan — Rainbow Gold Covering

The customer checkout now **shows payment types as disabled previews**. No Razorpay
payment is currently accepted. The existing store-provided UPI QR remains a **manual
UPI reference submission**, not proof of payment.

## Payment options intended for Razorpay Checkout
- UPI (supported methods depend on the merchant account)
- Credit/debit cards
- Net banking
- Supported wallets

These should be provided by a single verified Razorpay Standard Checkout instance,
not separate card forms collecting sensitive card information on this GitHub Pages website.

## When the Razorpay merchant account is available
1. Create Razorpay Test Mode keys in the merchant dashboard; store the public key ID
   in public runtime settings **only when ready**, and the key secret only in Supabase
   Edge Function secrets (never in GitHub, browser JavaScript, or committed HTML).
2. Implement a Supabase Edge Function that computes verified totals and creates a
   Razorpay order on the server in INR paise. It must reserve stock safely and track
   an idempotent pending checkout to avoid duplicate orders and inventory deductions.
3. Launch Razorpay Standard Checkout with the **server-created** order ID and
   server-calculated amount. Do not trust any browser-provided amount or "success".
4. Verify `razorpay_signature` on the server using the secret (HMAC SHA-256) and verify
   the payment is **captured** using Razorpay's API/webhook before marking the order paid.
5. Set up and verify Razorpay webhook signatures, idempotency, retries, and reconciliation
   for cases where customers close the browser or webhooks arrive late.
6. Run test-mode cases: success, failure, cancellation, duplicate callbacks, insufficient
   stock, and tampered amounts. Only then enable the disabled payment methods.
7. Handle refunds, settlements and support workflows in the admin dashboard.

## Future Edge Function secret names (not values)
- `RAZORPAY_KEY_ID` — gateway key ID.
- `RAZORPAY_KEY_SECRET` — **server-only** private key.
- `RAZORPAY_WEBHOOK_SECRET` — **server-only** webhook signing secret.

## Existing manual UPI QR limitations
- `assets/brand/pay.png` is a **static picture**, not generated by a gateway.
- Confirm the QR displays your merchant's UPI ID and name before taking payments.
- The site does not know whether an amount was paid; the entered UTR is only a claim.
- Verify receipt and the amount through your receiving bank/UPI provider before
  approving payment; never approve based only on customer-submitted UTR.
- State-based delivery is now calculated server-side: ₹50 Tamil Nadu, ₹100 other
  valid Indian states/UTs and included in the stored order/payment amount.
- Tax determination (CGST/SGST vs IGST for interstate orders) should be reviewed
  with your accountant before broadening interstate sales.

See the [official Razorpay integration documentation](https://razorpay.com/docs/payments/payment-gateway/web-integration/standard/integration-steps/).
